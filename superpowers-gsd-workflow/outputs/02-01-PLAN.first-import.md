# Plan 02-01: `-top N` flag

**Objective:** Add a `-top N` flag that prints the top N frequent words after the line/word counts.

**Source:** imported from `docs/superpowers/plans/2026-11-24-top-flag.md`. Spec: `docs/superpowers/specs/2026-11-24-top-flag-design.md`.

**Architecture:** An internal `scan` makes one pass producing `Counts` and a word-frequency map. `Count` becomes a wrapper (signature unchanged). A pure `Top` sorts and truncates. `run` parses flags and prints.

**Constraints:**
- All code in `main.go`, tests in `main_test.go`, table-driven (`[]struct{...}` + `t.Run`).
- Comments and error messages in English (match codebase); error prefix `tally:`.

**Review focus:**
- `"The the THE"` gives a single `the 3`.
- Ties `"b a c"` give `a 1`, `b 1`, `c 1`.
- Empty input with `-top 3` prints only `lines=0 words=0`.
- N above the distinct count prints all, no panic.
- Negative N gives exit 2 and empty stdout.

  <name>Task 1: Word frequency and sorting</name>
  <files>main.go, main_test.go</files>
  <action>
Add after `Count`: `type WordFreq struct { Word string; N int }`, `func scan(r io.Reader) (Counts, map[string]int, error)`, `func Top(freq map[string]int, n int) []WordFreq` (`n <= 0` returns nil; `n` over length returns all). `Top` collects a slice, `sort.Slice` by (count desc, word asc), truncates to n. `Count` calls `scan` and discards the map.

Test first (`TestTop`, table-driven; input goes through `scan`, then `Top`):
- `"The the THE\n", 3` → `[{the 3}]`
- `"b a c\n", 2` → `[{a 1} {b 1}]`
- `"a a b\n", 10` → `[{a 2} {b 1}]`
- `"", 3` → len 0
- `"a b\n", 0` → len 0
- Also assert `scan`'s Counts equals `Count` for the same input (`{Lines:1, Words:3}` for `"The the THE\n"`).
  </action>
  <verify>`go test ./... -run TestTop` fails to compile first (scan/Top undefined); after implementing, `go test ./...` passes, including the existing TestCount.</verify>
  <done>scan, Top and WordFreq exist; Count behavior is unchanged; all tests pass.</done>

<task type="auto" tdd="true">
  <name>Task 2: `-top` flag and output</name>
  <files>main.go, main_test.go, README.md</files>
  <action>
Add `func run(args []string, in io.Reader, out, errOut io.Writer) int`. `main` becomes `os.Exit(run(os.Args[1:], os.Stdin, os.Stdout, os.Stderr))`. Parse `-top` (int, default 0) with `flag.NewFlagSet`; a parse failure returns 2. Reject N<0 (see must_haves). Call `scan`, print the counts line, then for N>0 print each `Top` entry as `fmt.Fprintf(out, "%s %d\n", ...)`. A scan error prints `tally: <err>` and returns 1. Add a `-top N` example to the README usage section.

Test first (`TestRun`, table-driven; assert stdout and exit code):
- `[]`, `"a b c\n"` → `"lines=1 words=3\n"`, 0

- `["-top","2"]`, `"b a B c\n"` → `"lines=1 words=4\nb 2\na 1\n"`, 0
- `["-top","3"]`, `""` → `"lines=0 words=0\n"`, 0
- `["-top","-1"]`, `"a\n"` → empty stdout, stderr contains `tally: -top must be >= 0`, exit 2
  </action>
  <verify>`go test ./...` passes. `printf 'b a B c\n' | go run . -top 2` prints `lines=1 words=4`, `b 2`, `a 1`.</verify>
