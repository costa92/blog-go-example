# tally `-top N` 设计

状态：已批准（非交互运行，所有选择取推荐项，见下）。规模：小改动，短设计。

## 意图
统计输入中出现最频繁的词，让 tally 不止给总数。

## 目标 / 非目标
- 目标：`-top N`（默认 0）在原 `lines=… words=…` 行之后，逐行输出前 N 个词，格式 `word count`。
- 排序：次数降序；次数相同按词的字母序升序。
- 大小写不敏感：统计前 `strings.ToLower`。
- N=0 时输出与现在完全一致。
- 非目标：标点剥离、Unicode 分词、多文件、其他输出格式。
- 反目标：为此改变现有 `Count` 的签名或 `Counts` 的可比较性（现有测试用 `==`）。

## 约束
- stdin 只能读一次，行数/词数/词频必须同一遍扫描得出。
- 词的定义沿用现有的 `strings.Fields`（空白分隔），保证 top 里的次数总和与 `words=` 一致；"a," 与 "a" 是不同的词。

## 方案
1. **A（选定）**：新增内部 `scan(r) (Counts, map[string]int, error)`；`Count` 变成调用 `scan` 并丢弃词频的包装；新增纯函数 `Top(freq, n) []WordFreq`。`Counts` 与 `Count` 不动，旧测试不改。
2. B：给 `Counts` 加 `Freq map` 字段。map 使 `Counts` 不可比较，须改现有测试，且 N=0 也要付出建 map 的代价。
3. C：先读完全部 stdin 再分别算。大输入占内存，且仍要改签名。

选 A：改动最小、旧行为与测试零影响。

## 我的决定（供复核）
- 负数 N：报错 `tally: -top must be >= 0`，退出码 2。
- N 大于不同词数：输出全部，不报错。
- N=0 时不建词频 map 以外的额外输出；`scan` 总是统计词频（成本可忽略），不引入开关。
- 输出分隔符为单个空格。
