# 小模型先答、大模型兜底：本地 Agent 的模型路由

配套文章：[小模型先答、难题再交给大模型：3b 分不清题目难易，自报把握也不准，logprob 的优势取决于判分口径](https://costalong.com/2026/11/24/agent-model-routing/)。

150 道能自动判分的中文题（简单、中等、困难各 50），先让 qwen2.5-coder:3b 回答，再比较几种「什么时候交给 qwen2.5-coder:7b」的规则：让小模型自己判断难度、让它报一个 0 到 100 的把握、看答案 token 的 logprob、检查答案格式、温度 0.7 采样三次看是否一致。另外测 Ollama 在两个模型之间切换的加载代价，并真跑几种级联记录端到端耗时。

这是教学用的复现脚本，只覆盖一套题、一对模型，不是路由方案的基准。

## 文件

| 文件 | 作用 |
|---|---|
| `tasks.py` | 生成题库 `tasks.jsonl`，固定随机种子，重跑结果逐字节相同 |
| `run.py` | 对一个模型跑完整题库，`plain` 直接回答、`conf` 回答后报把握、`route` 只判断「简单 / 困难」 |
| `batch.sh` | 文章用到的全部 `run.py` 调用；默认每次调用前用 `flock ../../gpu.lock` 拿锁，单独使用时 `LOCK= ./batch.sh` |
| `judge.py` | 判分（看标准答案）和格式校验（不看标准答案，只查答案行的类型）；`correct` 是严格判分，`correct_lenient` 允许 JSON 拆行 |
| `grade.py` | 只读 `logs/`：各模型准确率、各种路由规则的离线模拟（严格和宽松判分各一遍）、信号的 AUROC、把握的校准；`python3 grade.py sweep` 扫阈值 |
| `swap.py` | 两个模型交替请求，测三种 `keep_alive` / `num_ctx` 组合下的加载时间，写 `logs/swap.jsonl` |
| `timing.sh` | 文章里的计时部分：`swap.py` 加五次 `cascade.py`，要放在一次 GPU 锁里连续跑 |
| `cascade.py` | 真跑一遍级联，记录每题端到端耗时，写 `logs/cascade.jsonl` |
| `show.py` | 打印某道题在某个日志里的原始输出 |
| `logs/` | 文章用到的原始结果；`logs/timing.txt` 是那次 `timing.sh` 的终端输出，配图里的切换截图取自这里；`logs/ollama-server-swap.txt` 是切换测试前两轮的 Ollama 服务日志摘录（只留调度相关的行，去掉了主机名和路径） |

## 运行

文章数据来自 Ollama 0.35.0、RTX 3060 12GB。

```bash
cd agent-model-routing
python3 tasks.py
LOCK= ./batch.sh                  # 约 1 到 2 小时
python3 grade.py
./timing.sh > logs/timing.txt     # 计时部分，约 30 分钟；GPU 上不要同时跑别的
```

不想重跑模型时，`python3 grade.py` 直接读仓库里的 `logs/`，可以先核对文章里的数字。自己重跑前先 `mv logs logs.article`：`run.py` 会跳过日志里已经有的题，`swap.py` 和 `cascade.py` 会把新结果接在旧日志后面。

## 验证与边界

- 温度 0 的结果都是单次运行（seed 1）；3b 和 7b 另有温度 0.7 的 3 个 seed，用来看波动和做自一致性规则。
- 只有一套 150 道自出的短题和一对同系列模型，题目偏算术和格式，不代表真实 Agent 请求。
- 主口径的判分偏严：JSON 必须写在答案行的同一行，拆成多行就算错。3b 有 9 道 JSON（m31、m33 到 m40）内容完全正确，只是拆了行，其中 7 道连答案行都没写。宽松判分（取输出里最后一个 `{...}`）下 3b 从 98 变成 107，logprob 的 AUROC 从 0.652 降到 0.539，`grade.py` 两种结果都会打印。
- 没有「答案：」行时，判分退回到最后一个非空行；3b 的 e45、e47、e49 是这样判对的。
- 格式校验里，人名必须出现在题面只对排序题生效，抽字段题的人名只要求是 2 到 3 个汉字。
- 答案 logprob 取的是答案行里所有 token 的最小值，换成平均值或只看第一个 token，阈值和效果都会变。
- 0.5b 当路由器时有 20 题没回答「简单 / 困难」而是直接答题，`grade.py` 把这类输出算作「其他」，按升级处理。
- `grade.py` 里的「计算耗时」是每次调用的耗时减去 Ollama 报告的 `load_duration` 再相加，不含加载和换模型；真实端到端耗时看 `cascade.jsonl`。
- 自一致性规则不升级时用第 1 次采样的答案，耗时算 3 次采样。
- 加载时间受硬件影响很大：文章数据里模型放在机械硬盘上，桌面程序常驻占着一部分显存（Ollama 日志里空载时空闲 7.7 GiB，共 11.6 GiB）。两个模型能否同时留在显存、先加载哪个会被驱逐，只在 Ollama 0.35.0 和这张卡上观察过。
- 计时时同机还有别的实验在排队等 GPU（没有并发），冷加载时间还受页缓存影响，只能当量级看。
- 文章提到的早期两版提示词（3b 照抄答案占位符、不写推理直接答）的日志没有放进仓库。
